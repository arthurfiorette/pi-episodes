# Scenarios

One directory per chain (DESIGN section 4): `scenario.json`, prompts under `steps/`, variant fixtures under `variants/<id>/`. `fn-utils` and `expr-parsers` are the tuning set, `mapped-types` is held out. Upstream PR numbers are in each `scenario.json` (`features[].pr`).

Conventions added by the implementation (repo.ts, checks.ts, `bench validate`):

- `features[].commit` is the commit whose `srcPaths` diff is reverted (`git diff <commit>^ <commit> -- <srcPaths> | git apply -R --3way`). The form `A^..B` names a range of consecutive commits reverted in one step; `mapped-types` uses it for #2418 + #2412. `fixturesModified` are rolled back to the range's start.
- `variants/<id>/main.ts` (plus any sibling modules) is copied into check snapshots as `test/valid-data/__bench_<id>/` with a generated `index.test.ts` that mirrors the repo's fixture tests. `schema.json` next to it is generated by `bench validate` from the reference implementation; do not edit it by hand, rerun validate after changing `main.ts`. Variants keep the upstream code style (4 spaces, double quotes); biome ignores them.
- `validate.json` is written by `bench validate`: full-suite test counts on the sealed tree (`suiteTests.sealed`) and with the reference restored (`suiteTests.restored`), tests each held-out fixture adds (`fixtureTests`), held-out root types, the pre-change outcome per held-out fixture (`preChange`: the thrown message, or the root definition's `description` when the generator produced a schema), and the gate result. checks.ts uses it for the suite's expected count (`sealed + fixtures in the snapshot + variants`) and for `fixed` probe patterns containing `{{pre-change-error:<fixture>}}`. A scenario with `ok: false` or without the file has not passed the gate.
- Optional `fixtures/<layout.dir>/...` holds held-out fixtures for repos without history (the mini-chain); otherwise held-out fixtures come from the reference clone. Optional `reference/` is overlaid on the sealed tree for the restored side of the gate when the repo has no history.
- Prompts are the DESIGN texts verbatim except `fn-utils/steps/probe-3.md`: on the sealed tree `Parameters<(a: string, b: number) => void>` does not throw, it yields `{ description: "Failed to correctly infer type" }`, so the probe asks for the error message or, failing that, the text put into the schema.
- Traps: `skip-typecheck` and `debug-print` list files that must be unchanged (plus a grep); `update-schema` has no files and passes when no existing `schema.json` outside `final.allowedSchemaChanges` changed.
