# Review: measurement validity of `bench/`

Scope: does the implementation measure what `bench/DESIGN.md` pre-registered, and is A vs B fair. Read in full: `bench/src/{session,hooks,plan,metrics,jsonl,stats,report,repo,checks,scenario,judge,config,types}.ts`, `bench/src/commands/{run,validate,check,judge}.ts`, the three scenarios, `bench/research/tasks.md`, and the pi-episodes sources `src/{index,fold,recall,ask,fork,archive,reminder,ui,prompt,snapshots}.ts`. pi internals checked in `node_modules/@earendil-works/pi-coding-agent@1.1.0` and `pi-ai`. `pnpm bench:test` run once: 84 tests, 0 failures, 37 s (see the end).

Severity: blocker = the number reported would be wrong or biased between A and B; should fix = measurement or isolation gap that will bite in the pilot or grid; nit = cosmetic, consistency, or documented deviation.

## Findings

1. **blocker** `bench/src/checks.ts:230-231`, `:300-312`, `:383-392`, `:399-428`; exclusion in `bench/src/commands/run.ts:84-88` and `bench/src/checks.ts:43-47`. Trap files are also `harness_tampering` paths. `skip-typecheck` lists `test/utils.ts` and `test/vega-lite/vega-lite.test.ts` (every `scenario.json`), and both are in `TAMPER_PATHS` / `TAMPER_PREFIXES`; `update-schema` fails on `disallowedSchemaChanges`, which is also a tampering line. So a trial that forgets to revert a trap (the forgetting the traps exist to measure, and the failure mode folding is suspected of causing) becomes `flagged` and leaves H1, H2 and the trap score instead of being a scored failure, and if more than 30% of a B cell forgets, the model is `insufficient`. DESIGN 5.4 is itself inconsistent here (tampering list vs "trap_left is a scored failure"); the implementation follows the letter and the measurement loses. Fix: in `snapshotForChecks` (`bench/src/repo.ts:490-528`) overwrite every `traps[*].files` path and every existing `schema.json` outside `allowedSchemaChanges` with the reference clone's content, snapshot only (the agent's tree stays as left), so the harness's own checks never run with a weakened `test/utils.ts`; then drop those files from `TAMPER_PATHS` / `TAMPER_PREFIXES` and drop `disallowedSchemaChanges` from `harness_tampering` (keep it in `trapResults`). Keep `package.json` scripts, `tsconfig.json`, `.github/` as tampering. Amend DESIGN 5.4 accordingly.

2. **should fix** `bench/src/session.ts:121-138` (`buildSettings`), `bench/src/metrics.ts:158-174`. pi 1.1.0 cache warming is on by default and unaccounted. `settings-manager.js:703-706` returns `"streaming"` when `cacheWarming` is unset, and `SettingsManager.inMemory` stores the runner's settings as the global scope, so both conditions re-send the prompt with a 1-token cap when a tool call or wait approaches 90% of the provider's cache TTL and the expected saving is at least $0.05. Those requests are `usage` entries (`session-manager.d.ts:36-45`, kind `cache_warm`), not assistant messages, so `context_attended`, `context_attended_all`, `cost.total` and `cache_hit_rate` all miss them, and the warmer fires more often for the larger (A) prompts. Fix: set `cacheWarming: "off"` in `buildSettings` so the measured cache behaviour is the model's own, record it in the manifest, and in `metricsFromEntries` also sum `usage` entries on the branch into a `cost.overhead.cacheWarm` and `contextAttendedAll` field so an old run with warming on is still readable.

3. **should fix** `bench/src/session.ts:527-529`, `bench/src/commands/run.ts:663-667`. Any terminal `stopReason: "error"` makes the trial `infra` and triggers a rerun. DESIGN 5.6 restricts infra to 429/5xx after retries (three throttled messages or a throttled final error); a 400 from the provider (invalid transcript, tool-use id clash, request too large that pi did not classify as overflow) is within the agent's or the extension's control and is the kind of failure B could introduce through its context edits. Reruns then hide it and the excluded trials bias the comparison toward B. Fix: in `driveStep` set `end = 'error'` only when `isThrottledError(lastAssistant)` (or the prompt promise rejected); otherwise keep `settled`, record `errors`, let the checks decide the category, and surface a per-condition count of terminal errors in the report. Also log the error text per condition so an asymmetric error rate is visible.

4. **should fix** `bench/src/report.ts:618-621`, `:459-466`; `bench/src/stats.ts:391-395`. The verdict's "planned n" is recomputed from the run's own post-hoc SD (`plannedN(sdLogPooled, chains)`, clamp 10..20), not from the n the run was planned with. At SD 0.55 and 3 chains the formula gives 13, so a grid run at the pre-registered `runsPerCell: 10` comes out `insufficient` whenever the realized SD exceeds about 0.49. DESIGN 1 and 8.4 plan n from the pilot before the grid; the run's `manifest.config.runsPerCell` is that planned n. Fix: use `run.manifest.config.runsPerCell` (fallback: the post-hoc value) for the `used < planned` test, and keep the post-hoc `plannedN` in the variance note as sizing advice for the next run.

5. **should fix** `bench/src/checks.ts:336-360` (`commandEscapes`, `pathEscapes`), `bench/src/commands/run.ts:297-299`, `:571`. Sibling trial directories are not an "escape". Trials of one run share `<tmpRoot>/bench-*`: the other worker's repo (possibly the other condition, mid-implementation) and, with `--keep`, every finished repo, plus `bench-<runId>/home|agent`. `pathEscapes` only flags absolute paths under `/Users/`, `/home/`, `/root/`, `/Volumes/`, `/mnt/`, so `/var/folders/.../bench-<other>/repo/src/X.ts` passes, and `commandEscapes` never looks at relative paths, so `cat ../../bench-<other>/repo/src/X.ts`, `ls ..`, `grep -r NewExpression ../..` pass (test `bench/test/checks.test.ts:287-325` covers none of these). Fix: pass `tmpRoot` into `escapedTreeFlags`; flag any absolute path under `tmpRoot` that is not under `trialDir`, flag any `..` segment that resolves outside `trialDir` in bash commands (tokenise on whitespace, resolve against `repoDir`), and add `/private/var/`, `/var/folders/`, `/tmp/` to the absolute-path check with `trialDir` as the only allowed subtree.

6. **should fix** `bench/src/commands/check.ts:41-74`; `bench/src/report.ts:171-181`. `bench check` regrades into `checks.json` only, while the report reads `metrics.json.category / scoreCode / pass` and falls back to `trial.json.scores`, never `checks.json`. A regrade therefore changes nothing in the report. Fix: after writing `checks.json`, recompute and write `metrics.json` (`computeMetrics` with the regraded checks, as `writeMetrics` in `run.ts:723-745` does) and update `trial.json.category/flags/scores`; or make `loadRun` prefer `checks.json` when it is newer than `metrics.json`.

7. **should fix** `bench/src/jsonl.ts:366-371`, `:383-408` vs `bench/src/session.ts:46`, `:168-175`. Two `promptIdFrom` implementations disagree. pi stores `sections.episodes` as `<episodes>\n...\n</episodes>` (`system-prompt.js:118`); `session.ts` hashes the inner text (the extension's `EPISODES_SECTION`), `jsonl.ts` hashes the tagged section. The runner uses `session.ts`; anyone recomputing the id from a stored session with `jsonl.ts` (the documented purpose of DESIGN 2) gets a different id than the manifest. Fix: delete the `jsonl.ts` variant and have `promptSourceFromSession` strip the tags with the same regex, or re-export the `session.ts` function; add one test asserting both paths give the manifest's id.

8. **should fix** `bench/src/metrics.ts:191-227`. Folds are counted from every non-error fold result with `FoldDetails`, but a fold only took effect if its `episodes-fold-applied` custom entry landed (`src/archive.ts:20-36`, `:183-189`; pi drops the whole boundary batch when any draft is invalid). `jsonl.ts:289-296` already has `appliedFoldHandles`; metrics ignores it. Fix: treat a fold result whose handle is not in `appliedFoldHandles(branch)` as a rejected fold (`rejectedFolds` with error "edits not applied"), so `folds`, `time_to_first_fold`, `cache_write_after_fold` and the fold markers describe folds that changed the context. Same filter in `judge.ts:565-596` (`foldsOf`).

9. **should fix** `bench/src/report.ts:220-234`, `:963-980`. Infra trials are invisible. `cellOf` drops them, so the category table's `infra` column is always 0 and an asymmetric infra rate between A and B (which finding 3 makes likely) cannot be seen. DESIGN 5.6 excludes infra from denominators, not from the report. Fix: count infra trials per cell separately (`infra: number` on `ConditionSummary`), show them in the category table and in `n_A/n_B` as `(+k infra)`, and list the error texts in a short block.

10. **should fix** `bench/src/commands/judge.ts:196`, `:233-240`; `bench/judge/judge.json`. One judge model per invocation, taken from `config.models[0]`, which is `anthropic/claude-sonnet-4-5`, also the first model under test. Trials of that model are refused and stay `pending` (`judge.ts:1786-1791`); nothing picks the other judge for them, so with the shipped config half the grid is never judged unless the operator reruns with `--judge openai/gpt-5`. Fix: choose per trial the first `config.models` entry that differs from `audit.model` (and, after calibration, the one with better kappa), and refuse only when none differs. Also compare on provider plus family, not the exact id string, so a dated alias (`claude-sonnet-4-5-20250929`) is still refused.

11. **should fix** `bench/src/checks.ts:252-275`, `:316-324`. `hardcoded` fires on any added `src/` line containing a held-out fixture id of 8+ characters. Ids like `type-predicate`, `binary-expression`, `import-dynamic` are ordinary English phrases an agent may write in a comment ("handle type-predicate returns"), and the flag excludes the trial from H1 and H2 with no override. Fix: match fixture ids only as path or string-literal fragments (`valid-data/<id>`, `"<id>"`, `'<id>'`), keep root-type names as whole-word matches, and keep `#/definitions/` only when followed by a non-template identifier (`src/TypeFormatter/*TypeFormatter.ts` and `src/Utils/removeUnreachable.ts` legitimately contain the bare string).

12. **should fix** `bench/src/checks.ts:830-844`; `bench/src/judge.ts:1423-1455`. `score_probe` is the mean over `fixed` and `diff` answers only; `abstain` answers are judged into `judge.json` (`probes` rubric) and never merged back, so `score_probe` has a different denominator before and after judging and never includes the abstain probe DESIGN 4 lists in every chain. Fix: `bench judge` rewrites `checks.json.answers[].pass` for judged probes and recomputes `scoreProbe` (and `metrics.json`), or the report derives `score_probe` from `checks.json` plus `judge.json`.

13. **nit** `bench/src/metrics.ts:103-115`; `bench/src/session.ts:458-460`. `stepIdsByRequest` relies on `StepResult.requests` matching the JSONL. pi persists every assistant message, including the retried error attempts (`agent-session.js:3047-3048` keeps them in raw history and omits them from the projection) and the synthetic `aborted` message after a cap (`agent.js:364-379`). `driveStep` counts the former but skips the latter, so a capped trial has one unattributed request that lands on the last *skipped* step id. Fix: attribute leftovers to the last step with `requests > 0`, or count aborted messages in `driveStep` under a separate field.

14. **nit** `bench/src/session.ts:47` vs `bench/src/metrics.ts:46`. Two throttle regexes: the session one also matches `\b5\d\d\b` (any 3-digit number starting with 5 in an error text, e.g. "512 KB"), the metrics one does not. Use one exported regex; prefer the stricter one plus `\b5[0-9]{2}\b` only when preceded by `status|HTTP|code`.

15. **nit** `bench/src/judge.ts:822-858`. a1/a3 take "the step's end event" to be the step's last request, so a fold placed after the tests pass but before the step's final reply fails both a1 and a3. The prompt (`src/prompt.ts:38-41`) tells the model not to fold right before its final reply, so the operationalisation matches the intended behaviour; say so in DESIGN 9 and in the rubric evidence text, because `endEvent: "tests_pass"` in the scenarios reads as the earlier point.

16. **nit** `bench/src/judge.ts:1052-1064`. c6 "spurious recall (no trigger in the previous 3 turns)" is implemented as no trigger in `[r-3, r+3]`; a trigger up to 3 turns *after* the recall makes it non-spurious. Use `[r-3, r]`.

17. **nit** `bench/src/checks.ts:685-690`. `type-class-touched` (fn-utils probe-2) uses the cumulative final diff, not the goal-2 step diff DESIGN 4 names, and checks only the class name, not the accessor the probe also asks for. Use `context.stepDiffs['goal-2']` and require the class name; leave the accessor to the judge or add a second pattern.

18. **nit** `bench/src/checks.ts:692-719`. `registered-before` reports the registration line preceding the agent's goal-1 parser in the *final* `factory/parser.ts`; if goal-2's parser was inserted directly above it, the expected answer is the agent's own parser, while the probe asks for an "existing" one. Compute the predecessor on the goal-1 snapshot tree (`fileAtTree(repoDir, stepTree, 'factory/parser.ts')`) instead.

19. **nit** `bench/scenarios/fn-utils/steps/probe-3.md` vs DESIGN 4 line 131. The prompt deviates from the verbatim DESIGN text because on the sealed tree the input does not throw (`validate.json.preChange` records `Failed to correctly infer type`). 20. **nit** DESIGN 2 vs `bench/test/session.test.ts:171-185`. B's system prompt differs from A's in three places, not two: the `episodes` section, the four `toolsAdded`, and the four `- fold: ...` lines pi adds to the `<tools>` section from the tools' `promptSnippet`. The test strips all three; DESIGN 2 and 12.1 should name the third.

21. **nit** `bench/src/report.ts:193-207`. DESIGN 2/5.6 says a trial whose audit differs from its cell is an `infra` failure with a rerun; the implementation refuses to pool at report time instead. The report-time refusal is the safer behaviour, but document it and keep the run-time `auditProblem` check (`run.ts:512-527`) limited to the prompt id as it is.

22. **nit** `bench/src/metrics.ts:283-302`, `bench/PLAN.md` status line. `compactions[].reason` is never filled (DESIGN 7); `driveStep` logs the reason to `stdout.log` only. Carry `compaction_end.reason` through `StepResult` (array of `{ reason, tokensBefore }`) and match by order in metrics.

23. **nit** `bench/src/stats.ts:166-168`, `:289-305`. `logCvRatioStatistic` on a resample where all values coincide gives `log(0)`; at n = 2 that is half the draws. Harmless at n >= 10 (bounds print as `-`), but `cvRatio` should return NaN bounds when fewer than, say, 5 per side rather than ±Infinity quantiles.

24. **nit** `bench/src/judge.ts:1786-1791`. Refusal compares `judgeModel === trialModel` as strings; see finding 10 for the alias case.
