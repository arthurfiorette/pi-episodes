# Review: runner robustness, cross-module consistency, operator experience

Scope: `bench/` (uncommitted) plus `package.json`, `tsconfig.json`, `.npmignore`, `.gitignore`, `biome.json`. Measurement validity (formulas, fairness, anti-leak) is covered by the other reviewer and is not repeated here. Everything below was checked against the code on 2026-10-14; claims marked "verified" were reproduced with a script or a command.

Baseline: `pnpm bench:test` twice, 84/84 green both times (37 s each); `pnpm lint`, `pnpm test-types` green; no files left under `bench/results/`, `bench/scenarios/*/validate.json` untouched, nothing new under `$TMPDIR` after the suite.

## Findings

1. **blocker** `bench/src/repo.ts:579-581` (`extractFinalTree`), hit by `bench/src/commands/check.ts:60`. The unpacked tree gets `node_modules` as a symlink to `bench/cache/node_modules-<sha>`. Node resolves imports from the real path, and that directory is not named `node_modules`, so `tsx` cannot find its own dependency: verified with a repo whose `node_modules` points at the template, `npx tsx --test test/valid-data/type-primitive/index.test.ts` fails with `ERR_MODULE_NOT_FOUND: Cannot find package 'esbuild' imported from .../node_modules-ddf5e6442036/tsx/dist/cli.mjs` (`npx tsc --noEmit` works because tsc is self-contained). On a real trial every fixture becomes `load_error`, the suite fails, and `bench check` overwrites a correct `checks.json` with `build_broken`. The e2e test passes only because mini-chain has no lockfile (no template, no symlink) and uses `node --test`. Fix: `await cloneTree(template, join(repoDir, 'node_modules'))` exactly as `setupTrialRepo` does at `repo.ts:328` (APFS clone, near-free), or lay the template out as `bench/cache/node_modules-<sha>/node_modules` and point both callers at that. `bench run` is not affected (trial repos get a cloned directory).

2. **blocker** `bench/src/commands/run.ts:154-165, 586-614` and `bench/src/session.ts:277-291`. Missing credentials and a missing reference repo are discovered inside each trial, after the full repo setup, and turn into `infra` plus reruns until every cell is exhausted; the run then exits 0. Verified: `pnpm bench run --runs 1 --scenarios mini-chain --run-id x` with no `auth.json` produced 12 infra trials (4 planned + 8 reruns), each with "no credentials for anthropic/openai", and `exit=0` because `run.ts:164` only looks at `pending`. On a real scenario each of those trials also copies the repo, applies the reverts and seals it first. Fix, in `runBench` before the dry runs: for `provider === 'real'` create one `ModelRuntime` with `options.authPath` and call `getModel` + `hasConfiguredAuth` for every model in `options.models`, throwing `ConfigError` with the same message `createTrialSession` uses; for every scenario call `ensureReferenceClone` + `ensureNodeModulesTemplate` once (this also moves the up-to-20-minute `npm ci` out of the first trial). Return 1 when any cell ended `insufficient` (an `infra` entry with no rerun scheduled), and stop the run after N consecutive `infra` trials (3 or 4): that pattern means the environment, not the provider, and each one can cost a full setup plus wasted API spend when it happens at snapshot time.

3. **should fix** `bench/src/jsonl.ts:359-408` vs `bench/src/session.ts:168-194`. Two `promptIdFrom` functions with the same name and different inputs compute different ids for the same session: `session.ts` hashes the text between `<episodes>\n` and `\n</episodes>`; `jsonl.ts` hashes `sections.episodes` as persisted, which includes the tags. Verified on `bench/test/fixtures/sessions/b-episodes.jsonl`: `promptIdFromSession` gives `3397fd04ee2d`, `promptIdFromSystemMessage` gives `3ad2a3039322` (the one in trial dir names and `manifest.promptIds`). Only `session.ts` is used by the runner; the `jsonl.ts` family (`promptIdFrom`, `promptSourceFromSession`, `promptIdFromSession`, `promptText`, `EPISODES_SECTION_NAME`) is reached only from `bench/test/jsonl.test.ts:156-191`, yet DESIGN 2 says the id "can be recomputed from any stored session", which is exactly what the wrong one promises. Fix: delete the `jsonl.ts` set and its test, or make `promptIdFromSession` delegate to `session.ts promptIdFromSystemMessage`; keep one formula with one test.

4. **should fix** `bench/src/session.ts:47` vs `bench/src/metrics.ts:46`. The throttle regex exists twice and differs: `session.ts` has `\b5\d\d\b`, which matches any three-digit number starting with 5 in an error text ("line 512", "503 tokens"); `metrics.ts` matches `529` only. `trial.json` `throttled` (drives the DESIGN 5.6 `infra` rule at `run.ts:678`) and `metrics.json` `errors.throttled` can disagree on the same session. Fix: one exported `isThrottledText(text)` in `jsonl.ts`, imported by both, with `\b5(0[023]|29)\b` instead of `5\d\d`.

5. **should fix** `bench/src/commands/run.ts:83-90, 496-507` vs `bench/src/checks.ts:42-47, 445-456`. DESIGN 5.5 ordering is implemented twice (`mergeCategory` + `EXCLUSION_FLAGS`, `pickCategory` + `EXCLUDING_FLAGS`). `hooks.finalize` already passes the harness outcome into `assembleChecks` (`hooks.ts:97-108, 269-274`), so `final.category` is the merged category; `run.ts:707` recomputes it and `writeMetrics` (`run.ts:738`) patches the category back into the checks "so the two files cannot disagree". Fix: delete `mergeCategory` and `EXCLUSION_FLAGS`; `record.category = harness.category === 'infra' || final === undefined ? 'infra' : final.category`. Keep the ordering test on `pickCategory`.

6. **should fix** `bench/src/repo.ts:56-64`, `bench/src/commands/run.ts` (no signal handling). The child-process reaper runs on `process.once('exit')`, and Node does not emit `exit` when the process dies from a signal. Verified: a `sleep 60` started through `runShell` survived `SIGINT` sent to the parent (`exit=130`, the `exit` listener never ran). Consequences on Ctrl-C or `kill`: a running full suite (10 cores, 60 to 70 s) or the agent's bash child keeps running, `runBench`'s `finally` never runs (isolated HOME/agent dir and trial scratch dirs stay), and `plan.json` is correct only because `running` is persisted before the trial starts. Fix: in `run.ts` install `process.once('SIGINT')` and `('SIGTERM')` that set a `stopping` flag (workers stop taking entries), kill every group in `running`, `abort()` the open sessions (keep the live `TrialSession`s in `SharedRun`), `savePlan`, `rmSync(runTmp)` unless `--keep`, then `process.exit(130)`. pi's dependency `signal-exit` already holds a SIGINT listener that re-raises the signal; a listener registered by bench runs before it.

7. **should fix** `bench/src/commands/run.ts:415-437, 449` and `bench/src/session.ts:449`. Exceptions can leave the worker: `runTrial` throws outside its `try` at `:547` (plan entry mismatch), in its `finally` at `:698` (`copySession` → `cpSync`, e.g. ENOSPC), and after it at `:712` (`writeTrial`); the worker's own `savePlan` at `:419/:434` can throw. One rejection makes `Promise.all` reject while the other worker's trial is mid-flight; `runBench`'s `finally` then deletes `runTmp` (the shared HOME and agent dir) under it, and `cli.ts:82` rethrows to an unhandled top-level rejection that prints the stack to stderr only. Separately `driveStep` does `void session.abort()`; `abort()` returns a promise, and a rejection there is an unhandled rejection, which Node turns into a crash. Fix: wrap the body of `worker` in try/catch that marks the entry `infra`, logs to `run.log` and continues; use `Promise.allSettled`; `session.abort().catch((error) => log.warn(...))`; add `process.on('unhandledRejection')` and `('uncaughtException')` in `run.ts` that write the error to `run.log` before anything else (a 75-hour `nohup` run otherwise loses the reason it died).

8. **should fix** `bench/src/commands/run.ts:571`. Trial scratch dirs are `<tmpRoot>/bench-<trialId>` with no run id in the name. Two `bench run` processes sharing a model label and scenario (two pilots, or a run next to `--keep` leftovers from an earlier one) use the same path, and `setupTrialRepo` (`repo.ts:324`) starts with `rmSync(repoDir)`: the second run deletes the first run's live repo under its agent. Fix: `tmpDir: join(runTmp, trialId)` (`runTmp` = `<tmpRoot>/bench-<runId>` already exists); update README line 87. Cleanup after a crash then becomes one `rm -rf`.

9. **should fix** `bench/src/commands/run.ts:173-189`. With `--resume` every other option is accepted by `assertKnown` and silently ignored (`--parallel`, `--models`, `--provider`, `--config`, `--runs`). An operator who resumes with `--parallel 1` after a 429 storm gets `parallel 2` again without a message. Fix: reject options other than `--keep` (and `--parallel`, which should override the manifest value) when `--resume` is given.

10. **should fix** `bench/src/cli.ts:42`, `bench/src/commands/judge.ts:35`, `bench/README.md:31`. The judge usage string and README omit `[--judge provider/model] [--config path] [--labels path]`, which `judge.ts` accepts. Also `bench <cmd> --help` reports "unknown option --help" before printing the usage (`cli.ts:74-77`); treat `--help` as a request for usage with exit 0.

11. **nit** `bench/src/commands/run.ts:183`. `--resume` reloads `scenario.json` and the prompt files from disk; an edited prompt between runs changes later trials silently while the manifest still says one scenario. Record a hash of `steps[].text` (and `final`, `variants`) per scenario in the manifest and refuse to resume when it moved, the same way prompt ids are checked at `:344-350`. (Measurement side belongs to the other reviewer.)

12. **nit** `bench/src/types.ts`. Overlaps from five owners: `TrialScores` (`:529`) repeats the four score fields of `ChecksJson` (`:325-327`) and `MetricsJson` (`:439-442`), with `hooks.ts:126-140 scoresOf` converting between them; the harness view exists three times (`HarnessOutcome.category` `:525`, `checks.ts SessionOutcome` booleans `:808`, `checks.ts CategoryInput` `:434`), with `hooks.ts:98-108` and `check.ts:20-38` each converting enum to booleans; `TrialSetup` (`:563`) duplicates two fields of `repo.ts TrialRepo`. ## Confirmed fine

- Trial-level containment: `runTrial` (`run.ts:585-705`) turns any throw from setup, session creation, the step driver, checks or finalize into `infra`, logs the stack to the trial's `stdout.log`, closes the session and runs `teardown` in `finally`; `teardown` runs when `setup` threw after creating the scratch dir (`:700`). Infra trials keep their results dir, get one rerun, two per cell (`plan.ts:131-150`), verified by `run.test.ts:305-335`.
- No resource leaks across sessions: a script that created, drove (4 steps) and disposed 8 B sessions in one process kept `process` listener counts (`exit`, `SIGINT`, `SIGTERM`, `unhandledRejection`), active handles and heap (58 MB) flat. `driveStep` clears its timer and unsubscribes in `finally` (`session.ts:520-525`); `closeTrialSession` emits `session_shutdown` then `dispose()` (`:389-395`), and pi-episodes' shutdown is bounded by its own git timeout.
- `plan.json` is written atomically (`plan.ts:50-55`, temp file + rename) at trial start (after marking `running`) and at trial end, including rerun scheduling; two workers call it synchronously so writes cannot interleave. `--resume` resets `running` to `pending`, deletes their results dirs and reruns them (`run.ts:353-356`, `run.test.ts:337-381`); a resume checks that the prompt id did not move. `bench report` on a half-finished run skips trial dirs without `session.jsonl`/`metrics.json` with a warning (`report.ts:139-159`).
- Process-wide isolated env is applied once per run before the dry runs and restored in `finally` (`run.ts:302, 450`); scenarios (which resolve `~`) are loaded before it. Shared state between parallel trials is limited to the plan array (synchronous mutations), the `prepared` promise map keyed by reference dir (`hooks.ts:144-162`) and the write-once settings; each trial has its own `Logger`, session, faux driver, `TrialState` (WeakMap).
- Disk: the sealed tree is 6.6 MB without `.git` (20 MB with), the `node_modules` template 164 MB (APFS-cloned per trial, so near-free on this machine), one snapshot copy of about 7 MB per goal step plus one final, `final-tree.tar.gz` a few MB with `.git`; scratch dirs are removed at teardown unless `--keep`, and the two leftover `<tmp>/bench-faux__*` dirs on this machine are from a manual `--keep` run. A full `/tmp` surfaces as `infra` at setup or snapshot time (see item 2 for the circuit breaker).
- Package wiring: `pnpm build` output has no `bench/` files (`tsconfig.build.json` includes `src/**/*.ts` only); `npm pack --dry-run --ignore-scripts` lists 0 `bench` files (the `*` whitelist already excludes it; the added `bench/` line is redundant but harmless); root `tsconfig.json` includes `bench/src` and `bench/test` so `pnpm test-types` covers them; `tsx` is a devDependency and `pnpm bench` resolves it; `.gitignore` covers `bench/results/`, `bench/cache/`, `bench/config/auth.json` and nothing else under `bench/`: all 126 other files, including `bench/test/fixtures/sessions/*.jsonl`, `b-episodes.episodes/fk-*.json`, the mini-chain repo and `bench/judge/labels.jsonl`, would be committed. `biome.json` overrides disable formatting for fixtures and variants only.
- `bench/README.md` matches the CLI for `run`, `validate`, `check`, `report`, `probe` and the results layout, config files, `extension` path semantics (relative to `bench/config/`, correct where DESIGN 11 writes `../src/index.ts`), the default `--reps 10000`, and the faux self-test commands; only the judge line (item 10) and the scratch dir path (item 8, if changed) need an update.
- Error messages: missing config, unknown model (`--models: unknown "nope"; have sonnet-4-5-med, gpt-5-med`), unknown scenario (ENOENT with the full `scenario.json` path), missing run for `check`/`report`/`judge`, and `bench --help` all print one readable line and exit 1 or 2; `probe` says "not implemented" and exits 2.
- `pnpm lint`, `pnpm test-types`, `pnpm bench:test` (x2) green; no `enum`, `namespace`, parameter properties or `import =` anywhere under `bench/`.
